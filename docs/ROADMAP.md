# 拾页 / Reading Garden 路线图

## 阶段总览

| 阶段 | 主题 | 状态 | 核心边界 |
| --- | --- | --- | --- |
| 0 | 环境与项目脚手架 | 已完成 | 只初始化工程，不写业务 |
| 1 | 产品、架构与阶段规划 | 当前阶段 | 只写文档，不改业务代码 |
| 2 | Supabase 基础、认证、数据库与 RLS | 未开始 | 先建安全底座，不做书籍/笔记功能 |
| 3 | 书架与阅读记录 | 未开始 | 只做个人书籍与阅读状态 |
| 4 | 笔记、可见性与搜索 | 未开始 | 只做笔记与个人搜索，不做公开社区 |
| 5 | 本地资料导入 | 未开始 | 只做 PDF/TXT/Markdown，不接外部平台 |
| 6 | 公开笔记流、主页与互动 | 未开始 | 只做轻量社区，不做关注和实时协作 |
| 7 | Chrome 扩展主动剪裁 | 未开始 | 只处理用户主动选择内容，不抓全文 |
| 8 | 微信读书导入与智能增强 | 未开始 | 仅使用已核验能力，未验证事项先阻塞 |

推进规则：一次只做一个阶段；上一阶段验收未通过，不进入下一阶段；数据库迁移和 RLS 变更前先建立可回退的 Git 节点。

## 阶段 0：环境与项目脚手架（已完成）

### 目标

建立可运行、可提交、可继续开发的 Next.js 工程底座。

### 交付物

- Next.js 16 App Router、React 19、TypeScript、Tailwind CSS、shadcn/ui 基础工程。
- 必要的 shadcn/ui 组件。
- `.env.example`、目录占位与 `.gitignore`。
- Git 仓库、首次提交和开发服务器启动验证。

### 前置依赖

- 无。

### 验收门槛

- Node.js 版本不低于 20.9，git 可用。
- 依赖安装完成，开发服务器可启动并实际返回成功响应。
- 已报告真实命令、版本、地址和结果。

### 本阶段不做

不实现产品页面、Supabase 连接、数据库结构、业务逻辑或外部服务集成。

## 阶段 1：产品、架构与阶段规划（当前阶段）

### 目标

固定产品范围、技术边界、数据模型、权限原则和后续阶段顺序，避免带着结构性歧义开始编码。

### 交付物

- `AGENTS.md`：工程、安全、测试和阶段推进规则。
- `docs/PRD.md`：定位、用户、场景、优先级、页面验收和首版边界。
- `docs/ARCHITECTURE.md`：架构原则、数据模型、权限、导入和外部接口边界。
- `docs/ROADMAP.md`：阶段 0–8 的目标、交付物、依赖和验收门槛。

### 前置依赖

- 阶段 0 已完成并通过用户确认。

### 验收门槛

- 四份文档均已创建或更新。
- 数据模型、可见性规则、功能优先级和阶段边界相互一致。
- 明确标注微信读书速率限制、Key 有效期和数据范围为“待验证”。
- 本阶段未修改 `app/`、`components/`、`lib/`，未安装依赖、未连接外部服务。

### 本阶段不做

不编写业务代码、数据库迁移、RLS 策略、登录页、页面 UI 或任何外部集成。

## 阶段 2：Supabase 基础、认证、数据库与 RLS

### 目标

建立 Supabase Auth、Postgres、Storage 和服务端鉴权基础，让后续数据访问从第一天起就受 RLS 约束。

### 交付物

- `lib/supabase/` 浏览器端、服务端与受控管理客户端封装。
- `profiles` 及基础数据表迁移。
- RLS 策略、必要索引和数据库约束。
- 私有 Storage bucket 与文件访问策略。
- 登录、退出、会话刷新和鉴权回调。
- 迁移前的可回退 Git 节点，以及数据库权限测试。

### 前置依赖

- 阶段 1 文档验收通过。
- Supabase 项目配置与本地/远端迁移策略已确认；凭据只进入未提交的环境变量。

### 验收门槛

- 匿名、普通用户、所有者三类访问的 RLS 测试全部通过。
- 私有 bucket 不可匿名访问，Service Role Key 不出现在客户端构建或日志。
- 迁移可重复执行并可从 Git 节点回退。
- 实际命令、测试结果与未执行项均有报告。

### 本阶段不做

不实现书籍 CRUD、笔记 CRUD、公开社区、导入器或 Chrome 扩展。

## 阶段 3：书架与阅读记录

### 目标

完成个人书籍管理和阅读状态闭环。

### 交付物

- `/library` 书籍列表、搜索、筛选与 CRUD。
- `/books/[id]` 书籍详情与阅读记录。
- 书籍、阅读记录的服务端校验与权限测试。
- 重复书籍检测所需的基础标识处理。

### 前置依赖

- 阶段 2 的认证、数据表和 RLS 通过验收。
- 迁移前建立可回退 Git 节点。

### 验收门槛

- 用户只能读取和修改自己的书籍与阅读记录。
- 非法状态、进度区间和重复标识有明确错误。
- 无权限访问返回 404/403，不泄漏资源内容。
- 页面在空、加载、错误和成功状态下均可用。

### 本阶段不做

不实现笔记、公开分享、评论、点赞、导入任务或外部平台同步。

## 阶段 4：笔记、可见性与搜索

### 目标

完成摘要、感想、引用、标签和个人搜索能力。

### 交付物

- `/write` 笔记创建与编辑。
- `/notes/[id]` 笔记详情。
- `private`、`public`、`unlisted` 三种可见性及不可猜测分享链接。
- 引用、标签、来源字段和个人范围搜索。
- 公开字段投影，避免泄漏私有附件和阅读记录。

### 前置依赖

- 阶段 3 的书籍模型与权限测试通过。
- 笔记可见性和 token 生成方案已确认。

### 验收门槛

- 三种可见性分别通过匿名、非所有者、所有者测试。
- `unlisted` 不出现在搜索或列表，链接 token 不可枚举。
- 引用与标签权限严格继承父笔记。
- 搜索只返回调用者有权读取的内容。

### 本阶段不做

不实现公开笔记流、个人主页、评论、点赞、关注、导入或扩展。

## 阶段 5：本地资料导入

### 目标

建立统一导入适配器和私有文件处理流程，支持 PDF、TXT、Markdown。

### 交付物

- `/import` 上传、校验、任务状态和错误反馈。
- `lib/importers/` 统一适配器接口及本地格式实现。
- `lib/validation/` 文件类型、大小、内容与字段校验。
- `import_jobs`、`private_files` 和私有 Storage 流程。
- 基础重复导入检测。

### 前置依赖

- 阶段 2 的私有 Storage 与阶段 4 的笔记模型通过验收。
- 导入数据格式与大小限制已确认。

### 验收门槛

- 支持格式成功导入，不支持格式、超限文件和解析失败均返回明确错误。
- 原始文件仅所有者可访问，不因笔记公开而公开。
- 同一来源重复导入不会静默生成重复记录。
- 不在未核验的情况下写死外部来源 endpoint 或伪造成功。

### 本阶段不做

不做微信读书导入、OCR、智能摘要、Chrome 扩展或公开文件访问。

## 阶段 6：公开笔记流、主页与互动

### 目标

形成轻量社区：只展示用户明确公开的内容，并支持基础互动。

### 交付物

- `/community` 公开笔记流。
- `/profile/[id]` 公开个人主页与本人管理视图。
- 评论、点赞及来源追踪。
- 公开内容分页、加载和空状态。
- 社区权限与隐私回归测试。

### 前置依赖

- 阶段 4 的可见性规则和阶段 5 的来源字段通过验收。
- 公开字段投影和互动权限策略完成设计。

### 验收门槛

- 公共列表只包含 `public` 笔记，排除 `private`、`unlisted`。
- 点赞满足 `(note_id, user_id)` 唯一约束。
- 评论和点赞不能越权访问私有笔记。
- 公开主页不展示私密书籍、笔记、阅读记录或附件。
- 未登录访客的可见范围符合 PRD。

### 本阶段不做

不做关注、共读、实时协作、重社交功能或公开原始文件。

## 阶段 7：Chrome 扩展主动剪裁

### 目标

让用户在浏览网页时主动选择片段，并安全导入为个人笔记草稿。

### 交付物

- `browser-extension/` Manifest V3 扩展。
- `activeTab`、`scripting`、`storage` 权限及用户确认流程。
- 扩展配对、服务端 token 校验和导入接口。
- 来源追踪与失败反馈。
- 配对、撤权和隐私测试。

### 前置依赖

- 阶段 6 的笔记来源和权限模型通过验收。
- 扩展配对流程及 endpoint 已完成安全核验，不得先写死未验证接口。

### 验收门槛

- 扩展不读取 Cookie、历史记录、登录凭证或未激活标签页内容。
- 只提交用户主动选择并确认的片段，不抓取全文。
- 配对 token 不写入日志或公开构建产物，用户可撤权。
- 服务端仍执行所有权、可见性和内容校验。

### 本阶段不做

不自动抓取正文、不读取 Cookie/历史、不做静默后台采集、不集成微信读书。

## 阶段 8：微信读书导入与智能增强

### 目标

接入已核验的微信读书只读能力，并按验证结果逐步提供 OCR、智能摘要、关注与共读。

### 交付物

- 微信读书只读适配器，使用服务端 Agent Skill + API Gateway。
- 书架、笔记划线、阅读统计、书籍搜索的导入流程。
- `Authorization: Bearer $WEREAD_API_KEY` 的服务端鉴权封装。
- OCR、智能摘要、关注与共读的分项设计与实现。
- 外部服务失败、限流和 Key 失效的可读错误处理。

### 前置依赖

- 阶段 7 及此前阶段全部通过验收。
- 官方当前文档确认速率限制、Key 有效期、可读取数据范围和返回结构。
- 外部接口、字段和权限边界完成核验；核验前保持阻塞。
- 服务端密钥管理与日志脱敏方案通过检查。

### 验收门槛

- API Key 只在服务端使用，不持久化明文、不写日志、不进入客户端。
- 只调用已核验 endpoint 与字段；失败时明确报告，不伪造成功。
- 只读能力符合官方当前说明；待验证项有明确结论或继续阻塞。
- OCR、摘要、关注与共读分别通过权限、错误和边界测试后才可交付。

### 本阶段不做

不接入未授权微信读书接口，不公开整本版权内容，不默认公开原始 PDF 或阅读记录，不做实时协作和重社交。
