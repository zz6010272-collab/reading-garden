# 拾页 / Reading Garden 路线图

## 阶段总览

| 阶段 | 主题 | 状态 | 核心边界 |
| --- | --- | --- | --- |
| 0 | 环境初始化与脚手架 | 已完成 | 只初始化工程与开发环境，不写业务 |
| 1 | 规划文档 AGENTS/PRD/ARCHITECTURE/ROADMAP | 已完成 | 只写文档，不改业务代码 |
| 2 | UI 框架：9 个页面 + 可复用组件 + mock 数据 | 未开始 | 只使用类型明确的 mock，不接真实数据库 |
| 3 | Supabase 基础：Auth、Postgres、RLS、私有 Storage | 未开始 | 建立安全底座并验证两名用户隔离 |
| 4 | 核心读书：书籍、笔记、搜索、公开笔记与互动 | 未开始 | 完成真实数据闭环，不做导入与外部集成 |
| 5 | 文件导入：PDF、TXT、Markdown | 未开始 | 只做本地文件提取、私有存储与去重 |
| 6 | 微信读书导入 | 未开始 | 只使用官方 Agent Skill 受控能力，保留手动导入 |
| 7 | Chrome 扩展 | 未开始 | 只做 Manifest V3 主动剪裁与配对鉴权 |
| 8 | 测试与部署 | 未开始 | 安全检查、上线报告、README 与部署准备 |

推进规则：一次只做一个阶段；上一阶段验收未通过，不进入下一阶段；数据库迁移和 RLS 变更前先建立可回退的 Git 节点。

当前路线图只安排阶段 0–8。PRD 中的 OCR、智能摘要、关注与共读暂不排入当前阶段，后续需要单独确认范围与安全边界。

## 阶段 0：环境初始化与脚手架（已完成）

### 目标

建立可运行、可提交、可继续开发的 Next.js 工程底座。

### 交付物

- Next.js 16 App Router、React 19、TypeScript、Tailwind CSS、shadcn/ui 基础工程。
- 必要的 shadcn/ui 组件。
- `.env.example`、目录占位与 `.gitignore`。
- Git 仓库、首次提交和开发服务器启动验证。

### 前置依赖

- 无。

### 验收门槛

- Node.js 版本不低于 20.9，git 可用。
- 依赖安装完成，开发服务器可启动并实际返回成功响应。
- 已报告真实命令、版本、地址和结果。

### 本阶段不做

不实现产品页面、Supabase 连接、数据库结构、业务逻辑或外部服务集成。

## 阶段 1：规划文档 AGENTS/PRD/ARCHITECTURE/ROADMAP（已完成）

### 目标

固定产品范围、技术边界、数据模型、权限原则和后续阶段顺序，避免带着结构性歧义开始编码。

### 交付物

- `AGENTS.md`：工程、安全、测试和阶段推进规则。
- `docs/PRD.md`：定位、用户、场景、优先级、页面验收和首版边界。
- `docs/ARCHITECTURE.md`：架构原则、数据模型、权限、导入和外部接口边界。
- `docs/ROADMAP.md`：阶段 0–8 的目标、交付物、依赖、验收门槛和范围边界。

### 前置依赖

- 阶段 0 已完成并通过用户确认。

### 验收门槛

- 四份文档均已创建或更新。
- 数据模型、可见性规则、功能优先级和阶段边界相互一致。
- 明确标注微信读书速率限制、Key 有效期和数据范围为“待验证”。
- 路线图阶段顺序与项目实际的 UI-first 推进顺序一致。
- 本阶段未修改 `app/`、`components/`、`lib/`，未安装依赖、未连接外部服务。

### 本阶段不做

不编写业务代码、数据库迁移、RLS 策略、登录页、页面 UI 或任何外部集成。

## 阶段 2：UI 框架 —— 9 个页面 + 可复用组件 + mock 数据

### 目标

完成 9 个页面的完整 UI 框架、可复用组件和类型明确的示例数据（mock），先验证信息架构、交互流程与视觉体系；本阶段不接真实数据库。

### 交付物

- 9 个页面及路由骨架：`/`、`/library`、`/books/[id]`、`/notes/[id]`、`/write`、`/community`、`/profile/[id]`、`/import`、`/settings`。
- 共享布局、导航、页面标题、空状态、加载状态和错误状态。
- 可复用业务组件与 `components/ui/` 基础组件的组合使用。
- 类型明确的 mock 数据与 fixtures，覆盖书籍、笔记、用户、评论、点赞、导入任务等页面状态。
- `private`、`public`、`unlisted` 的界面表现与可见性提示。
- 响应式布局和基础可访问性支持。
- 服务端/客户端边界示例；Next.js 16 的 `params`、`searchParams` 按 Promise 处理。

### 前置依赖

- 阶段 1 的四份文档通过验收。
- PRD 中 9 个页面的目标与验收条件已确认。
- mock 数据结构与 ARCHITECTURE 中的实体和权限语义保持一致。

### 验收门槛

- 9 个路由均可启动并通过 mock 数据展示主要状态，不依赖 Supabase 环境变量。
- `npm run dev` 可启动，`npm run build` 通过，并报告真实结果。
- mock 数据有明确类型和来源标识，不在界面中伪装成真实持久化数据。
- 私有、公开和 unlisted 状态在界面上有清晰区分。
- 页面在桌面与移动尺寸下可用，空状态、错误状态和操作反馈完整。
- 未执行真实写库、真实鉴权或任何外部接口调用。

### 本阶段不做

本阶段不做：不接 Supabase、不写真实 CRUD、不调用外部接口、不安装新依赖（除非 UI 必需）。

## 阶段 3：Supabase 基础 —— Auth、Postgres 迁移、RLS、私有 Storage

### 目标

建立 Supabase Auth、Postgres、Storage 和服务端鉴权基础，让后续数据访问从第一天起就受 RLS 约束，并验证用户隔离。

### 交付物

- `lib/supabase/` 浏览器端、服务端与受控管理客户端封装。
- `profiles` 及核心数据表迁移。
- RLS 策略、必要索引和数据库约束。
- 私有 Storage bucket 与文件访问策略。
- 登录、退出、会话刷新和鉴权回调。
- 迁移前的可回退 Git 节点，以及两名用户的隔离测试。

### 前置依赖

- 阶段 2 的页面框架与 mock 数据通过验收。
- Supabase 项目配置与本地/远端迁移策略已确认；凭据只进入未提交的环境变量。
- 数据库迁移和 RLS 变更前建立可回退的 Git 节点。

### 验收门槛

- 匿名、普通用户、所有者三类访问的 RLS 测试全部通过。
- 使用两名真实测试用户完成隔离验证：用户 A 无法读取或修改用户 B 的私有数据。
- 私有 bucket 不可匿名访问，Service Role Key 不出现在客户端构建或日志。
- 迁移可重复执行并可从 Git 节点回退。
- 实际命令、测试结果与未执行项均有报告。

### 本阶段不做

不实现书籍 CRUD、笔记 CRUD、公开社区、文件导入器、微信读书或 Chrome 扩展。

## 阶段 4：核心读书 —— 书籍、笔记、搜索、公开笔记与互动

### 目标

完成真实数据驱动的书籍、阅读记录、笔记、搜索、公开分享、个人主页、评论和点赞闭环。

### 交付物

- `/library` 书籍列表、搜索、筛选与 CRUD。
- `/books/[id]` 书籍详情与阅读记录。
- `/write` 笔记创建与编辑，支持引用、标签和来源字段。
- `/notes/[id]` 笔记详情，支持 `private`、`public`、`unlisted`。
- 个人范围搜索，以及公开内容检索。
- `/community` 公开笔记流。
- `/profile/[id]` 公开个人主页与本人管理视图。
- 评论、点赞及互动权限测试。
- 书籍、笔记、搜索、公开字段投影和互动权限的回归测试。

### 前置依赖

- 阶段 3 的认证、数据表、RLS 和两名用户隔离测试通过。
- 笔记可见性、unlisted token 和公开字段投影方案已确认。
- 数据库迁移和 RLS 变更前建立可回退的 Git 节点。

### 验收门槛

- 两名用户不能读取或修改对方的私有书籍、阅读记录和笔记。
- 三种笔记可见性分别通过匿名、非所有者、所有者测试。
- 公共列表只包含 `public` 笔记，排除 `private`、`unlisted`。
- 点赞满足 `(note_id, user_id)` 唯一约束，评论和点赞不能越权访问私有笔记。
- 公开主页不展示私密书籍、笔记、阅读记录或附件。
- 搜索只返回调用者有权读取的内容。
- 所有 CRUD、空状态、加载状态和错误状态均使用真实数据验证。

### 本阶段不做

不做文件导入、微信读书导入、Chrome 扩展、关注、共读、实时协作或部署上线。

## 阶段 5：文件导入 —— PDF、TXT、Markdown、文字提取与去重

### 目标

建立统一导入适配器和私有文件处理流程，支持 PDF、TXT、Markdown 的文件上传、文字提取和重复检测。

### 交付物

- `/import` 上传、校验、任务状态和错误反馈。
- `lib/importers/` 统一适配器接口及 PDF、TXT、Markdown 实现。
- `lib/validation/` 文件类型、大小、内容与字段校验。
- PDF、TXT、Markdown 的文字提取流程。
- `import_jobs`、`private_files` 和私有 Storage 流程。
- 基于内容哈希或来源标识的重复导入检测。
- 手动创建笔记始终可用，不依赖导入成功。

### 前置依赖

- 阶段 4 的笔记、来源字段和权限模型通过验收。
- 阶段 3 的私有 Storage 与 RLS 通过验收。
- 导入数据格式、文件大小限制和文字提取方案已确认。

### 验收门槛

- PDF、TXT、Markdown 成功导入并提取可审阅文本；不支持格式、超限文件和解析失败均返回明确错误。
- 原始文件仅所有者可访问，不因笔记公开而公开。
- 同一来源或相同内容哈希重复导入不会静默生成重复记录。
- 导入任务状态、失败原因和重试入口真实可见。
- 未出现外部接口调用或伪造成功响应。

### 本阶段不做

不做微信读书导入、OCR、智能摘要、Chrome 扩展或公开原始文件。

## 阶段 6：微信读书导入 —— 官方 Agent Skill 受控导入

### 目标

基于官方 Agent Skill + API Gateway 提供受控的微信读书只读导入，同时保证手动导入功能始终可用。

### 交付物

- 微信读书只读适配器，使用服务端 Agent Skill + API Gateway。
- 书架、笔记划线、阅读统计、书籍搜索的导入流程。
- `Authorization: Bearer $WEREAD_API_KEY` 的服务端鉴权封装。
- 统一导入格式映射、来源追踪、导入任务和错误反馈。
- 手动导入入口与微信读书导入的清晰分流。
- 外部服务失败、限流和 Key 失效的可读错误处理。

### 前置依赖

- 阶段 5 的文件导入和重复检测通过验收。
- 官方当前说明确认 API Gateway 地址、鉴权头、返回结构和只读能力。
- 速率限制、Key 有效期和可读取数据范围完成核验；核验前保持阻塞。
- 服务端密钥管理与日志脱敏方案通过检查。

### 验收门槛

- 手动导入始终可用，微信读书不可用时不影响核心读书流程。
- API Key 只在服务端使用，不持久化明文、不写日志、不进入客户端。
- 只调用已核验 endpoint 与字段；失败时明确报告，不伪造成功。
- 只读能力符合官方当前说明；待验证项有明确结论或继续阻塞。
- 来源数据转换后可通过阶段 5 统一适配器进入书籍或笔记流程。

### 本阶段不做

不接入未授权微信读书接口，不公开整本版权内容，不默认公开原始 PDF 或阅读记录，不做 OCR、智能摘要、关注、共读或 Chrome 扩展。

## 阶段 7：Chrome 扩展 —— Manifest V3、主动剪裁与配对鉴权

### 目标

让用户在浏览网页时主动选择片段，并安全导入为个人笔记草稿。

### 交付物

- `browser-extension/` Manifest V3 扩展。
- `activeTab`、`scripting`、`storage` 权限及用户确认流程。
- 扩展配对、服务端 token 校验和导入接口。
- 来源追踪、导入结果与失败反馈。
- 配对、撤权和隐私测试。

### 前置依赖

- 阶段 6 及此前阶段全部通过验收。
- 扩展配对流程及 endpoint 已完成安全核验，不得先写死未验证接口。
- 手动笔记与导入能力已验证可用。

### 验收门槛

- 扩展不读取 Cookie、历史记录、登录凭证或未激活标签页内容。
- 只提交用户主动选择并确认的片段，不抓取全文。
- 配对 token 不写入日志或公开构建产物，用户可撤权。
- 服务端仍执行所有权、可见性和内容校验。
- 微信读书或扩展服务不可用时，手动导入和核心读书流程仍可用。

### 本阶段不做

不自动抓取正文、不读取 Cookie/历史、不做静默后台采集、不绕过用户确认、不导入整本版权内容。

## 阶段 8：测试与部署 —— 安全检查、上线报告、README 与部署准备

### 目标

完成全项目安全与功能验收，整理可复现的测试结果和上线检查报告，补齐 README，并做好部署准备。

### 交付物

- 覆盖登录、权限、书籍、笔记、搜索、互动、导入和扩展的测试清单及真实结果。
- RLS、私有 Storage、Service Role Key、环境变量、日志脱敏和越权路径的安全检查。
- 两名用户隔离、匿名访问、private/public/unlisted 的最终回归测试。
- README：环境要求、安装、环境变量、开发、测试、构建、迁移和部署步骤。
- 上线检查报告：未解决问题、已知风险、回退方案和发布清单。
- 部署准备：环境变量模板、迁移顺序、健康检查、备份与回滚说明。

### 前置依赖

- 阶段 0–7 全部通过验收。
- 工作区干净，所有数据库迁移和 RLS 变更已有可回退 Git 节点。
- 部署目标、环境变量和回滚策略已确认。
- 不在本阶段引入未排期的新功能。

### 验收门槛

- `npm run lint`、`npm run build` 和项目约定的测试命令全部执行并报告真实结果。
- 未运行的检查必须有明确原因，不能以“已完成”替代测试。
- 安全检查未发现匿名读取私有数据、客户端暴露 Service Role Key 或私有文件匿名访问。
- README 能让新环境按文档完成启动、迁移和构建。
- 上线检查报告明确列出通过项、阻塞项、风险和回退方案。
- 获得用户确认后才可执行真实生产部署。

### 本阶段不做

不新增业务功能，不临时修改数据结构规避测试，不使用真实用户数据做破坏性测试，不在未确认的情况下发布生产环境。
